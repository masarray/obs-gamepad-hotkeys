# Security Policy

Security reports are welcome and should be handled privately whenever possible.

## Supported versions

Security fixes are applied to the latest public release and the current `main` branch. Older preview releases may not receive separate fixes.

## Reporting a vulnerability

Please **do not publish exploit details, malicious files, credentials, signing material, or sensitive system information in a public issue**.

Preferred reporting path:

1. Use GitHub's **Report a vulnerability** / private security advisory flow for this repository when it is available.
2. Include the affected version, OBS version, Windows version, reproduction steps, expected impact, and the smallest safe proof of concept needed to reproduce the issue.
3. Do not attach real credentials, private keys, certificates, or unrelated personal data.

If private vulnerability reporting is not available, open a minimal public issue stating that you need a private security contact, but **do not include vulnerability details** in that issue.

## Scope

Examples of security-relevant reports include:

- unsafe installer path handling or arbitrary file overwrite;
- code execution outside the intended plugin/install flow;
- unsafe parsing of persisted configuration;
- privilege-boundary or signing-related flaws;
- dependency/bootstrap behavior that could execute untrusted content;
- release artifact integrity problems.

Normal controller compatibility problems, OBS action mapping bugs, UI issues, and feature requests should use the regular issue tracker instead.

## Release integrity

Official Windows binaries are published only through this repository's GitHub Releases. Each Setup EXE and manual ZIP is accompanied by a SHA-256 manifest generated by CI.

Users should not disable Microsoft Defender, SmartScreen, Smart App Control, or organizational security policy to install the plugin. A reputation warning for an unsigned/new binary is different from a malware detection; follow the guidance in the README and official release page.

## Disclosure

Please allow maintainers reasonable time to validate and fix a security issue before public disclosure. Once a fix is available, the project may publish a concise advisory and remediation guidance.
